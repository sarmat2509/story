# Реестр HTTP endpoints WonderTales

Снимок на 2026-07-17. Runtime-источник — фактические `app.use(...)` в `services/api/src/index.ts` и регистрации `router.get/post/put/patch/delete(...)` в `services/api/src/routes`. Test-источник — explicit manifest `services/api/src/testing/httpEndpointManifest.ts`. Registry contract требует их точного совпадения.

## Итог

- Всего: **200 endpoints** в **40 router-модулях**.
- `/api/v1`: **172**.
- `/ssr`: **21**.
- `/health`: **4**.
- `/share-card`: **2**.
- `/sitemap.xml`: **1**.
- С прямым `requireAuth` либо router-level `router.use(requireAuth, ...)`: **143**. Без credentials для них базовое ожидание — `401`.
- Без прямого `requireAuth`: **57**. Это public/optional-auth JSON, auth entrypoints, assets, webhooks, SSR/share/sitemap. Для них нельзя ставить общее ожидание `401`: статус зависит от валидности входа, подписи, наличия ресурса и типа route.

## Текущее HTTP-покрытие

- `httpEndpointRegistryContract.test.ts` проверяет exact match всех **200 из 200** mounted routes с explicit manifest, отсутствие дубликатов и существование назначенного `testOwner`.
- `clientApiAuthorizationContract.test.ts` проверяет `401` для **143 из 143** защищённых endpoints.
- `adminApiAuthorizationContract.test.ts` проверяет `403` для **46 из 46** admin-only endpoints с валидной сессией обычного пользователя.
- `sessionModeAuthorizationContract.test.ts` проверяет parent-only и strict child-only routes с неправильным session mode.
- `test:api-contracts` запускает **44** route/domain contract files; последний прогон — **44/44 passed**.
- High-risk happy/error contracts есть для generation, continuations, auth/session, billing/webhooks, health/ops, assets, SSR, public stories, quiz, map/artifacts, profile/privacy, children/characters и representative admin operations.
- Наличие route в manifest означает явный test owner, но не обязательно successful input-output test. Часть admin/legacy routes пока покрыта только access и validation branches.

Domain/service tests и Playwright API mocks не считаются HTTP happy-path покрытием endpoint. Подробная глубина и оставшиеся gaps: `docs/api-test-coverage.md`.

| `requireAuth + requireAdmin`         |                                   `401` |                     обычный user: `403` |                                                route-specific success |
| `requireAuth + requireParentSession` |                                   `401` |                    child session: `403` |                                                route-specific success |
| `requireAuth + requireChildSession`  |                                   `401` |                   parent session: `403` |                                                route-specific success |
| optional/public JSON                 | не `401` только из-за отсутствия токена |              policy может вернуть `403` |                     обычно `200`, create feedback `201`, rating `200` |
