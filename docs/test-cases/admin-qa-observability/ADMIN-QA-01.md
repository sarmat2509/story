# ADMIN-QA-01 Найти историю в admin после основного сценария
[Назад к index](../README.md)


- ID: `ADMIN-QA-01`
- Модуль: `Admin-панель как инструмент QA`
- Приоритет: `P1`

## Контекст

Этот кейс описывает только поиск истории в `Admin / Stories`. Подготовка usage для лимитных сценариев вынесена в отдельный кейс `ADMIN-QA-07`.

## Что проверяем

После основного пользовательского сценария QA может найти нужную историю в `Admin / Stories` по `storyId` или точному заголовку и открыть ее детали.

## Точки входа

| Раздел | Web URL | Навигация внутри приложения |
| --- | --- | --- |
| Список историй в admin | <https://magic-sleep-time.duckdns.org/admin/stories> | Web-only: `Профиль` -> `Admin` -> `Admin / Stories` |
| Детали истории в admin | `https://magic-sleep-time.duckdns.org/admin/stories/<storyId>` | В таблице нажать `Open story` |

## Предусловия

- Есть пользователь `ADMIN_USER` с ролью admin.
- Проверка выполняется в web-версии.
- В текущем прогоне уже создана история типа `DRAFT_STORY`, `PUBLISHED_PUBLIC_STORY` или `PUBLISHED_UNLISTED_STORY`.
- QA заранее зафиксировал точный `storyId` или точный заголовок этой истории в основном продукте.

## Шаги проверки

1. Войдите под `ADMIN_USER` и откройте <https://magic-sleep-time.duckdns.org/admin/stories>.
2. В поле `Search by story title or id` введите точный `storyId` или точный заголовок истории из основного сценария.
3. Если история не появилась в таблице, переключите фильтр `All`, `Published`, `Unlisted` или `Private`.
4. Найдите строку истории в таблице.
5. Нажмите `Open story`.

## Ожидаемый результат

- В таблице `Admin / Stories` появляется строка с тем же `storyId`, что и в основном продукте.
- Статус в таблице совпадает с пользовательским сценарием: `Private`, `Published for all` или `Unlisted`.
- Кнопка `Open story` открывает страницу `admin/stories/<storyId>` именно для найденной истории.
- QA не обязан вручную искать историю в БД или по логам, чтобы подтвердить ее наличие.
