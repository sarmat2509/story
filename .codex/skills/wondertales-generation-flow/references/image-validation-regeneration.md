## Scene Image Generation

Regular story images are generated by `processStoryImages` and `generateSceneImageWithReference` in `services/api/src/services/storyOrchestrationService.ts`.

Domain: `services/api/src/domain/image/ImageDomainService.ts`.

Prompt builders:

- `services/api/src/prompts/image/ImagePrompts.ts`
- `services/api/src/prompts/image/ImageEditPrompt.ts`
- `services/api/src/prompts/image/ImageValidationPrompt.ts`
- `services/api/src/prompts/image/TurnaroundPrompt.ts`
- `services/api/src/prompts/image/MapTilePrompt.ts`

Reference inputs can include:

- environment reference plates
- character identity references or turnaround sheets
- outfit plates
- previous scene references
- Files API URIs or inline base64

`generateSceneImageWithReference` builds reference instructions, assigns image indices, resolves character outfits, composes scene visual with environment context, then calls the image domain.

## Scene Image Routes

- First pass usually uses simple route: `getImageDomainService()`.
- Validation retry/fallback can use complex route: `getComplexImageDomainService()`.
- Manual scene regeneration starts with complex route.
- Environment and outfit references use the simple image route.
- Turnaround sheets use dedicated service in `turnaroundSheetService.ts`.

Provider config is described in `wondertales-project-map/references/providers-runtime.md`.

## Segmented Scene Image Validation

Production runner: `services/api/src/domain/image/imageValidationRun.ts`.

Important facts:

- `ImageDomainService.validateGeneratedImage` is a legacy method name and delegates to `validateGeneratedImageSegmented`.
- `validateGeneratedImageSegmented` calls `runSegmentedProductImageValidation`.
- It sends one generated image plus character identity/outfit references.
- It runs optional layout pass and per-character identity passes.
- Request manifest records image order, reference metadata, model, pass data.
- Results are scored by `computeValidationScore` in `storyOrchestrationService.ts`.
- Acceptance is `score > IMAGE_VALIDATION_MIN_ACCEPT_SCORE`.

Validation output persists to `image_validation_results` through `imageValidationPersistenceService.ts`.

Admin listing route: `services/api/src/routes/imageValidations.ts`.

## Scene Validation Retry and Repair

Inside `generateSceneImageWithReference`:

- `maxAttempts` is capped to at most two image attempts for normal validation loop.
- On low score, rejected images are saved detached for diagnostics.
- If `IMAGE_VALIDATION_USE_EDIT_REPAIR=true`, it tries `editSceneImageUsingValidationFeedback`.
- Edit repair builds a targeted repair plan:
  - identity repair references only for characters needing identity repair
  - outfit references only for characters needing outfit repair
- If edit repair fails, it falls back to full regeneration.
- If every attempt scores below threshold, it selects the best scored attempt rather than blindly using the last.
- Generated image safety can still block upload before asset creation.

`editSceneImageUsingValidationFeedback` calls `ImageDomainService.editSceneImage`, which uses provider `editImage` support and `buildImageEditPrompt`.

## Repair/Edit Prompt

If the task is to inspect the exact repair/edit prompt string, do not start from provider adapters or script search. Start from the prompt builder and then walk outward.

Exact prompt builder:

- `services/api/src/prompts/image/ImageEditPrompt.ts`
- `buildImageEditPrompt(...)` returns the edit instruction string.
- `buildImageEditSystemInstruction()` returns the separate system instruction used for validation repair edits.
- `targetedRepairManifest` is the preferred structured input. `targetedRepairInstruction` is a deprecated fallback for older callers.

Runtime call path:

- `services/api/src/services/storyOrchestrationService.ts`
- `buildTargetedEditRepairPlan(...)` selects identity/outfit references and builds the repair manifest from validator output.
- `editSceneImageUsingValidationFeedback(...)` calls `imageDomain.editSceneImage(...)` with `targetedRepairManifest` and `buildImageEditSystemInstruction()`.
- `services/api/src/domain/image/ImageDomainService.ts`
- `editSceneImage(...)` calls `buildImageEditPrompt(...)`, logs `editInstructionsPreview`, then sends `editInstructions` to provider `editImage(...)`.

For an exact string, call or import `buildImageEditPrompt(...)` with a real or fixture `ImageValidationResult` plus the targeted repair manifest. For production debugging, reconstruct those inputs from the failing validation row and scene context, then compare with `editInstructionsPreview` in logs. The provider receives the already-built `editInstructions`; it is not the source of the repair prompt.

## Manual Scene Regeneration

Routes:

- User: `POST /api/v1/stories/:id/scenes/:sceneId/regenerate`
- Admin: `POST /api/v1/admin/stories/:storyId/scenes/:sceneId/regenerate-image`

Queue:

- `storyJobQueue.addJob({ type: "regenerate_scene_image", ... })`
- durable legacy queue

Service:

- `regenerateSceneImage(storyId, sceneId, visualPrompt?)`

Behavior:

- Keeps old image until replacement passes validation and is saved.
- Builds `initialEditRepair` from current scene image if possible.
- Reloads story metadata, linked characters, child profile, LLM characters.
- Reuses existing environment/outfit references when available.
- Ensures LLM turnarounds for scene characters.
- Builds validation/reference arrays.
- Calls `generateSceneImageWithReference` with `initialImageRoute: "complex"` and possible initial edit repair.
- Updates `scenes.imageUrl`, story cover asset, then deletes old image assets.

## Comic Page Validation

Comic page validation is not the same as scene segmented validation.

- Method: `ImageDomainService.validateGraphicNovelPagePanels`.
- Runner: `runGraphicNovelPanelImageValidation`.
- It sends the full comic page plus references in a single panel-array request.
- It checks expected panel count, panel visual focus/setting, expected characters, extra structure, text/artifacts.
- Art validation uses `includeLayoutChecks: true` and `includeBubbleChecks: false` before bubbles are overlaid.
- Page repair threshold is `GRAPHIC_NOVEL_ART_REPAIR_THRESHOLD` in `graphicNovelOrchestrationService.ts`.

## Map Tiles

Route: `POST /api/v1/stories/:id/map-tile`.

Service: `services/api/src/services/mapTileGenerationService.ts`.

Map tile brief normally comes from Director output persisted as `stories.metadata.mapTile`. Request body can override it.

Generation:

- chooses a mask from `domain/story/mapTileMasks.ts`
- optionally attaches up to three existing story scene images as references
- uses `getMapTileImageDomainService()`
- stores output as an `assets` row and updates `stories.metadata.mapTileAssetId` and `mapTileMaskId`
- relinks collected map tiles when a story tile is regenerated

Mask PNGs are generated by `services/api/src/scripts/generateMapTileMasks.ts`.
