## Майлстоун 1 — Шаринг и публичный просмотр

**Статус:** не реализовано

**Описание:** Пользователь должен иметь возможность поделиться сказкой — отправить ссылку, по которой получатель сможет прочитать историю без регистрации. Это ключевая виральная механика продукта.

**Scope:**

### Backend
- Эндпоинт `POST /api/v1/stories/:id/share` — генерирует публичный токен (короткий, уникальный)
- Эндпоинт `GET /api/v1/share/:token` — возвращает данные истории (текст, сцены, изображения) без авторизации
- Таблица `story_shares` (или поле `share_token` в `stories`) для хранения токенов
- Настраиваемый срок жизни ссылки (по умолчанию — бессрочно)
- Rate limiting на публичный эндпоинт

### Frontend
- Кнопка «Поделиться» в Story Viewer
- Модальное окно с копированием ссылки
- Публичная страница-вьювер (без навигации приложения, только чтение + прослушивание)
- Обложка-карточка для превью в мессенджерах (Open Graph мета-теги)

### Критерии готовности
- [ ] Пользователь нажимает «Поделиться» и получает ссылку
- [ ] По ссылке открывается история без логина
- [ ] В мессенджерах показывается превью (обложка + заголовок)

## Майлстоун 2 — Завершение серий (SeriesBible, арки, антиповторы)

**Статус:** частично реализовано (базовые продолжения работают, но нет планирования арок и защиты от повторов)

**Описание:** Сериал из 5–7 эпизодов должен иметь общую арку, рост персонажа, финал. Сейчас продолжения генерируются ad-hoc без планирования и без проверки на повторения.

**Scope:**

### Backend
- **SeriesBible** — JSON-структура при создании серии:
  - персонажи (цели, страхи, привычки, речевые особенности)
  - мир (правила, места)
  - главная моральная арка
  - запреты (чего не делать)
  - список уникальных событий, которые нельзя повторять
- **SeasonArc** — план на 5–7 эпизодов:
  - цель каждого эпизода, уникальный hook, cliffhanger
  - финальный эпизод: закрытие хвостов, возврат мотивов
- **ContinuityState** — состояние между эпизодами:
  - факты («что уже произошло»)
  - открытые нити
  - использованные морали и hooks
- **Anti-repeat gates:**
  - проверка уникальности поворотов, конфликтов, моральных выводов
  - ограничение на количество новых сущностей за эпизод
- Обновление `ContinuationPrompt` для использования всех артефактов серии

### Frontend
- Экран управления серией: план сезона, прогресс (эпизод 3/7)
- Кнопка «Создать следующий эпизод» с учётом плана
- Превью арки (краткое содержание серии)

### Критерии готовности
- [ ] При создании серии генерируется SeriesBible + SeasonArc
- [ ] Каждый новый эпизод учитывает ContinuityState
- [ ] Повторяющиеся повороты/морали отклоняются и заменяются
- [ ] Финальный эпизод закрывает все сюжетные нити

## Майлстоун 3 — Policy Engine: авторемонт и цикл проверок

**Статус:** частично реализовано (правила в БД, валидация текста через AI есть, но нет цикла авторемонта)

**Описание:** Модель не должна писать «как хочет» — каждый этап генерации проходит проверку, и при нарушениях система автоматически исправляет фрагмент или предлагает безопасную альтернативу.

**Scope:**

### Backend
- **Многоэтапная проверка** (сейчас только текст):
  - Outline (сцены) — проверить до генерации текста
  - Финальный текст — проверить после генерации
  - Alt-текст к иллюстрациям — проверить промпты
  - Текст для озвучки — финальная проверка
- **Цикл авторемонта (self-heal):**
  - Если не прошло — «перепиши только сцену N»
  - «Смягчи конфликт», «упрости лексику»
  - Максимум 2–3 итерации, затем блокировка с объяснением
- **Логирование причин блокировок/ремонтов:**
  - Таблица или поле для хранения причин
  - Метрики: % блокировок, % ремонтов, по возрастным группам

### Критерии готовности
- [ ] Outline проверяется перед генерацией текста
- [ ] При нарушении текст автоматически переписывается (до 3 итераций)
- [ ] Промпты иллюстраций проверяются на безопасность
- [ ] Причины блокировок логируются

## Майлстоун 4 — Режим сна (Sleep Mode)

**Статус:** не реализовано

**Описание:** Премиум-фича для ритуала засыпания: спокойная озвучка с постепенным затуханием, белый шум, таймер выключения.

**Scope:**

### Frontend
- **Таймер сна:** 5 / 10 / 15 / 20 / 30 минут
- **Затухание громкости:** плавное снижение громкости за последние 2–3 минуты
- **Фоновые звуки** (опционально): белый шум, дождь, камин, колыбельная мелодия
  - Микширование с озвучкой
  - Отдельный регулятор громкости
- **Авто-переход к спокойным концовкам** — при включении sleep mode не генерировать напряжённые сцены
- UI: кнопка «Режим сна» в аудиоплеере, настройки таймера

### Backend
- Параметр `night_mode` в запросе TTS (уже частично есть: скорость/тональность)
- Набор фоновых звуков в asset storage
- Флаг `sleep_mode` в StoryRequest для адаптации контента

### Критерии готовности
- [ ] Таймер останавливает воспроизведение через заданное время
- [ ] Громкость плавно снижается перед остановкой
- [ ] Можно включить фоновый звук поверх озвучки
- [ ] В sleep mode генерируется более спокойный контент

## Майлстоун 5 — Лендинг: SEO, FAQ, демо

**Статус:** частично реализовано (базовый LandingScreen есть, но нет SSR, FAQ, демо)

**Описание:** Лендинг — основная точка входа для привлечения пользователей. Должен быть оптимизирован для поисковиков, содержать демо и FAQ.

**Scope:**

- **FAQ секция:** 10–15 популярных вопросов (безопасность, возраст, языки, подписка)
- **Демо-секция:** 2–3 примера историй с иллюстрациями (статичные, без генерации)
- **«Как это работает»:** 3 шага с иконками/скриншотами
- **Секция безопасности/педагогики:** описание возрастного движка и правил
- **Цены:** интеграция блока с планами на лендинг
- **Open Graph мета-теги** для шаринга в соцсетях
- **SSR/SEO** (фаза 2): рассмотреть Next.js для лендинга или pre-rendering

### Критерии готовности
- [ ] Лендинг содержит FAQ, демо, «как работает», безопасность, цены
- [ ] При шаринге ссылки на лендинг отображается превью
- [ ] Лендинг доступен на всех поддерживаемых языках

## Майлстоун 6 — Интеграция платежей

**Статус:** не реализовано (планы и лимиты есть, оплата — заглушка)

**Описание:** Реальный биллинг: пользователь оплачивает подписку, система автоматически обновляет план и лимиты.

**Scope:**

### Backend
- **Stripe** (для веба):
  - Checkout Session для подписки
  - Webhook для обработки событий (payment_succeeded, subscription_updated, subscription_deleted)
  - Customer portal для управления подпиской
- **RevenueCat** (для мобильных):
  - Интеграция SDK
  - Верификация покупок на сервере
  - Синхронизация плана между платформами
- **Синхронизация:** один пользователь — один план, независимо от платформы оплаты
- **Семейный план** (фаза 2): до 4 детей, совместная библиотека

### Frontend
- Экран оплаты: выбор плана → оплата → подтверждение
- Управление подпиской в настройках (текущий план, дата продления, отмена)
- Paywall при превышении лимитов

### Критерии готовности
- [ ] Пользователь может оплатить подписку (web: Stripe, mobile: IAP)
- [ ] После оплаты план и лимиты обновляются автоматически
- [ ] При отмене подписка действует до конца оплаченного периода
- [ ] Webhook обрабатывает все ключевые события Stripe

## Майлстоун 7 — Админ-панель

**Статус:** не реализовано

**Описание:** Отдельное React SPA для управления контентом, пользователями, голосами, модерацией и аналитикой.

**Scope:**

### Инфраструктура
- Отдельное приложение `apps/admin-panel` (React + Vite + Tailwind + shadcn/ui)
- Admin-авторизация (email/password, JWT, RBAC: super_admin, content_moderator, support)
- Таблицы `admin_users`, `admin_audit_log`
- Middleware `requireAdmin` с ролевым контролем
- Все действия логируются в audit log

### Модули
1. **Дашборд:**
   - Карточки: пользователи, истории, конверсия
   - Графики: истории/день, регистрации, языки, популярные голоса
   - Здоровье системы: API, БД, rate limiters

2. **Управление голосами:**
   - Список TTS-голосов с фильтрами и поиском
   - Добавление/редактирование голоса (провайдер, язык, пол, возраст, роль, теги)
   - Привязка к возрастным группам
   - Прослушивание sample и тестовая генерация

3. **Управление возрастными группами:**
   - CRUD с валидацией (нельзя удалить используемую)

4. **Управление пользователями:**
   - Поиск, фильтры, детальная карточка
   - Impersonate (генерация JWT для пользователя)
   - Бан, удаление аккаунта
   - Сброс счётчиков использования

5. **Модерация историй:**
   - Список историй с фильтрами
   - Детальный просмотр: текст, картинки, аудио, стоимость генерации
   - Очередь жалоб (flagged): пользовательские + автоматические
   - Действия: одобрить, удалить, отредактировать, связаться с пользователем

6. **Аналитика:**
   - API calls по эндпоинтам (количество, latency, ошибки)
   - Стоимость генерации по типам (текст, изображения, аудио)
   - Логи ошибок с фильтрами

### Критерии готовности
- [ ] Админ логинится и видит дашборд с реальными данными
- [ ] Можно добавить/редактировать/тестировать TTS-голос через UI
- [ ] Можно найти пользователя и просмотреть его детали
- [ ] Можно модерировать историю (flag/delete)
- [ ] Все действия логируются в audit log

## Майлстоун 9 — Аналитика и метрики

**Статус:** не реализовано

**Описание:** Трекинг ключевых продуктовых метрик для понимания эффективности продукта.

**Scope:**

### Метрики (из концепта)
- **Activation:** % пользователей, создавших первую сказку за 5 минут после регистрации
- **Conversion:** free → paid (воронка)
- **Retention:** D1, D7, D30 (ритуал сна — главный драйвер)
- **Share rate:** % сказок, которыми поделились
- **Story completion rate:** % дослушавших/дочитавших до конца
- **Safety incident rate:** % блокировок/жалоб
- **COGS per story:** себестоимость генерации (текст + картинки + аудио)

### Реализация
- Таблица `analytics_events` (или внешний сервис: Amplitude, Mixpanel, PostHog)
- Трекинг событий на фронте: story_created, story_shared, story_completed, audio_started, audio_completed, plan_upgraded
- Backend: стоимость каждой генерации (токены, картинки, символы TTS)
- Дашборд в админ-панели (или внешний сервис)

### Критерии готовности
- [ ] Ключевые события трекаются (создание, шаринг, прослушивание)
- [ ] Можно посмотреть activation/conversion/retention в дашборде
- [ ] COGS per story рассчитывается автоматически

**Scope:**

### Флоу
1. Ребёнок рисует героя или предмет
2. Родитель фотографирует (камера или галерея)
3. Система анализирует изображение: извлекает сущности (кто/что нарисовано)
4. Предлагает 4–6 сценариев с этим героем
5. Генерирует историю и иллюстрации, включающие нарисованного героя

### Backend
- Эндпоинт загрузки рисунка/фото → AI-анализ (описание персонажа/предмета)
- Генерация сценариев на основе анализа
- Включение описания в prompt для иллюстраций (IP-Adapter / style reference)

### Frontend
- Режим «Сказка з малюнка» в визарде
- Загрузка фото (камера/галерея)
- Превью: «Мы увидели: дракон с крыльями» → выбор сценария
- Настройки приватности: автоудаление фото (по умолчанию)

### Критерии готовности
- [ ] Пользователь загружает рисунок и получает описание
- [ ] Система предлагает сценарии на основе рисунка
- [ ] В сгенерированной истории и картинках присутствует нарисованный герой
- [ ] Фото удаляется автоматически (или по настройке)

## Майлстоун 12 — Роутинг с локалями и Deep Links

**Статус:** не реализовано

**Описание:** URL-роутинг с префиксом локали для SEO и правильного шаринга; deep links для перехода из мессенджера в приложение.

**Scope:**

### Web-роутинг с локалями
- Все публичные маршруты: `/{locale}/`, `/{locale}/pricing`, `/{locale}/faq`
- Все приватные маршруты: `/{locale}/app/...`
- Алиас `/ua/` → `uk` (для украинской локали)
- Fallback: неизвестная локаль → `en`
- Share-ссылки: `/{locale}/s/{token}`
- Cookie `locale` для запоминания выбора

### Deep Links
- Universal Links (iOS) / App Links (Android)
- Сценарий: пользователь нажимает ссылку в Telegram → открывается приложение на нужном экране
- Fallback: если приложение не установлено → открывается web-viewer

### Критерии готовности
- [ ] URL содержит локаль: `/uk/`, `/en/`, `/ru/`, `/es/`
- [ ] Переключение языка меняет URL
- [ ] Share-ссылка с локалью открывает историю на правильном языке
- [ ] Deep link из мессенджера открывает приложение (или web-viewer)

## Майлстоун 15 — Консистентность персонажей (улучшение)

**Статус:** частично реализовано (есть reference image tracking, но нет формальных Character Sheet и проверки сходства)

**Описание:** Во всех иллюстрациях серии персонажи должны выглядеть одинаково (лицо, одежда, стиль).

**Scope:**

### Backend
- **Character Sheet** как формальная JSON-структура:
  - каноническое описание внешности
  - 2–5 референс-изображений (создаются при первом появлении)
  - запрещённые изменения (возраст, пол, цвет глаз)
- **Проверка консистентности** (фаза 2):
  - Face embedding: сравнение лица на новой иллюстрации с каноном
  - Автоматическая перегенерация при сходстве ниже порога
- **Детектор артефактов** (фаза 2):
  - Проверка на «сломанные лица/руки»
  - Эвристики + модель качества

### Критерии готовности
- [ ] При создании персонажа генерируется Character Sheet
- [ ] Все сцены серии используют одинаковые референсы
- [ ] (Фаза 2) Перегенерация при низком сходстве с каноном

## Майлстоун 17 — Self-Hosted генерация изображений

**Статус:** не реализовано

**Описание:** Снижение себестоимости за счёт локальной генерации вместо API. Также позволяет использовать IP-Adapter и ControlNet для лучшей консистентности.

**Scope:**

### Инфраструктура
- ComfyUI + SDXL checkpoint
- InstantID (identity по одному фото)
- IP-Adapter (стиль/персонаж как референс)
- ControlNet (опционально: pose/depth/sketch)
- GPU сервер (12+ GB VRAM)

### Интеграция
- Job worker для обработки очереди сцен
- REST API: `/render_scene` принимает IllustrationPlan.scene → возвращает URL
- Retry policy + degraded mode (1024 → 768, high → medium → low)
- Кэширование по (scene_hash, style, character_version)

### Quality Gates
- Безопасность: блокировка запрещённых тем, NSFW classifier
- Консистентность: face embedding проверка
- Артефакты: детектор «сломанных лиц/рук»

### Критерии готовности
- [ ] Изображения генерируются на собственном GPU
- [ ] Персонажи консистентны через InstantID/IP-Adapter
- [ ] Качество сравнимо с API-генерацией
- [ ] Себестоимость ниже API в 3–5 раз
